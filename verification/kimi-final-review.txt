# Advisory Review: Omarchy Doctor 1.0.0

## 1. `abortScan()` leaves the deadline timer armed (QML event ordering)
**Location:** `Doctor.qml` — `abortScan()`
**Trigger:** User cancels a scan, then stays on the panel. `deadline` was restarted in `refresh()` and is never stopped by `abortScan()`. Up to 100 s later `deadline.onTriggered` fires, overwrites `scanError` with *"Scan exceeded its deadline. Results are partial."*, forces `complete=false`, and sets `collector.running=false` on an already-dead process.
**Fix:** Add `deadline.stop()` to `abortScan()`. (Compare `collector.onExited`, which correctly calls `deadline.stop()`.)

## 2. Change detection compares across scan modes, producing false "resolved/changed" signals (history correctness)
**Location:** `doctor.py` — `History.save()`
**Trigger:** Run a deep scan where `packages` is `warn`, then a quick scan. In quick mode `packages()` returns state `skipped`, so `save()` records `change="changed"` and appends `{"from": "warn", "to": "skipped"}` to `changes` — the Overview then reports "1 check state(s) changed", implying a real system change that never happened. The inverse (deep after quick) reports the check as `"new"`.
**Fix:** Skip change computation when the current row is `skipped` (leave `change` empty / mark `"not measured"`), or only compare rows whose domain was measured in both scans (e.g., store mode per row and compare only same-mode predecessors).

## 3. Restoring an archived scan marks it unconditionally complete (false healthy)
**Location:** `Doctor.qml` — `ingest()`, `e.type==="history"` branch
**Trigger:** A scan that was cancelled or hit the deadline is saved via `History.save()` with whatever rows exist (partial scans are still inserted). On next open, `results=scans[0].rows; complete=true` is set unconditionally. The Overview then shows the "SCAN COMPLETE" header and computes the headline via `Model.state(results, complete=true)`, upgrading what was a partial scan to a full-coverage verdict (e.g., "Looking good" when several checks never ran and aren't even in `rows`).
**Fix:** Persist a `complete` flag in the `scans` table (schema bump or infer `len(rows) == len(CHECKS)` in QML: `complete = scans[0].rows.length === total`) and restore it instead of hard-coding `true`.

## 4. `--enable` failure loses the install receipt and backup path (installation safety)
**Location:** `install.py` — `main()`, `if args.enable:` block
**Trigger:** `omarchy-shell shell rescanPlugins` or `omarchy bar put` fails (shell not running, section name changed). `CalledProcessError` propagates before the receipt is written, so `installation.json` — the only record of the timestamped backup directory containing the previous `shell.json` and plugin copy — is never created, and the user sees a traceback for an installation that actually succeeded.
**Fix:** Write the receipt immediately after the atomic swap (before the enable steps), and wrap the two enable commands in `try/except subprocess.CalledProcessError` that prints a warning and reports `"enabled": false` in the receipt.

## 5. Live vitals samples are silently discarded on every history reload (history correctness, minor)
**Location:** `Doctor.qml` — `ingest()`, `e.type==="history"` vs `"vitals"`
**Trigger:** The `"vitals"` handler merges live samples into `historySamples` (`past.push(...)`), but every `"history"` event (fired by `loadHistory()` on open, on `scan_end`, and on each range change) replaces `historySamples` wholesale with `e.samples`. Because `doctor.py` only persists watch samples to SQLite while the panel is open and a scan-triggered `loadHistory()` can race ahead of the next watch tick, any live samples not yet written to the DB vanish from the graph until the next reload.
**Fix:** In the `"history"` branch, merge instead of replace: keep `historySamples` entries newer than the newest DB sample, e.g. `var cutoff = e.samples.length ? e.samples[e.samples.length-1].timestamp : 0; historySamples = (e.samples||[]).concat(historySamples.filter(function(s){return s.timestamp > cutoff}))`.

---

**Verified as correct (not findings):** timeout/kill lifecycle in `Runner` (process-group kill, `CHILDREN` discard in `finally`, timeout returning before pipe reads); `drives()` treating smartctl timeout/127 as `unknown` rather than healthy; `packages` deep-mode incomplete-output guard; retention deletes in `History`; installer's staged rename with rollback on `stage.rename` failure.
