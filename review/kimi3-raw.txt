# Bug review — Omarchy Doctor plugin

## Confirmed defects

**1. High — `doctor-checks.sh` `check_temperature` (~line 100) — sensor limits read as current temperature.**
Trigger: any `sensors` text output containing `high = +85.0°C` / `crit = +100.0°C` lines. The regex `grep -Eo '\+[0-9]+([.][0-9]+)?°C'` matches those lines, `sort -nr` picks `100.0`, and the plugin emits `bad … 100°C` on a machine at 48°C. Earlier review claim #1 is **correct**. Fix: use `sensors -j` and read only input fields (e.g. keys ending `_input`), or grep only lines matching `^\s*\w.*input` semantics; never mix thresholds with readings.

**2. High — `doctor-checks.sh` `check_failed_services` (~line 24) and `check_journal` (~line 40) — command failure reported as healthy.**
Both use `var=$(cmd … || true)` and treat empty output as success. If `systemctl --failed` or `journalctl` errors (no session bus, corrupted journal), `$failed`/`$errors` is empty → emits `ok "No failed systemd units."` / `ok "No … errors found"`. Same pattern in `check_packages`: `pacman -Qk 2>/dev/null` with a locked/absent DB yields empty output → `grep -vc` = 0 → `ok`. Earlier review claim #2 (shell half) is **correct**. Fix: capture exit codes explicitly (`if ! out=$(cmd); then emit info/warn "…check unavailable…"; return; fi`).

**3. Medium — `Doctor.qml` `overallStatus` (line 21) + `collector.onExited` — misleading health verdict.**
`overallStatus` returns `"ok"` whenever `results.length > 0` and no bad/warn, so an all-`info` scan (e.g. minimal system: no sensors, no pacman, no bluetooth) shows "All systems healthy". Separately, `onExited` only surfaces collector failure when zero rows parsed; a script that dies mid-run (e.g. killed during `check_packages`) silently reports partial results as a complete scan. Earlier review claim #2 (QML half) is **correct**. Fix: treat `info`-only as a distinct "incomplete" state; on nonzero exit with partial rows, append an `info`/`warn` "scan incomplete" row instead of ignoring it.

**4. Medium — `doctor-checks.sh` top level + `Doctor.qml` `refresh`/`Timer` — no timeout anywhere; one blocked command freezes the scan forever.**
Trigger: any probe that blocks (e.g. `systemctl` hanging on a stuck D-Bus call, `pacman -Qk` waiting on `/var/lib/pacman/db.lck`, `nvidia-smi` hanging on a wedged driver). Checks run sequentially with no deadline; `StdioCollector{waitForEnd:true}` never completes, `scanning` stays true, the button stays disabled, middle-click and `R` silently no-op (`refresh()` returns when `collector.running`). Earlier review claim #3 is **correct as a mechanism**; actual hangs are environment-dependent. Fix: wrap probes in `timeout` (e.g. `timeout 10 systemctl …`), emit an `info` row on timeout; optionally kill the Process after a deadline in QML.

**5. Medium — `doctor-checks.sh` `check_storage_health` (~line 225) — wrong disk checked, mislabeled "primary".**
`lsblk -dnpo NAME,TYPE | awk '$2=="disk"{print $1; exit}'` picks the first disk in kernel enumeration order, which need not back `/`. On multi-disk systems the summary "SMART reports the primary disk as healthy" can certify an unrelated drive while the root disk is unchecked. Earlier review claim #5 is **correct**. Fix: resolve the device behind `/` via `findmnt -n -o SOURCE /` + `lsblk -no PKNAME`, iterate all parent disks, and name each device in the summary.

**6. Low — `design/doctor-concept.html` — two pause-motion classes desynchronize.**
`setMotion` toggles `.paused` on `<body>`; the `visibilitychange` handler toggles `.paused` on `<html>` (`documentElement`). After hiding/showing the tab, `<html>` retains `paused`; clicking "Resume motion" clears only `body.paused`, so motion stays paused while `aria-pressed="false"` claims otherwise. Fix: use one element/class for both paths.

## Hypothesis needing native Quickshell validation

**7. Medium — `Doctor.qml` `onMoveRequested` (~line 163) — keyboard scroll uses hardcoded 76px row stride.**
Delegate height is `rowColumn.implicitHeight + 18`, and the summary `Text` has `wrapMode: WordWrap`, so rows vary. `selectedIndex * 76` will scroll to the wrong offset for wrapped rows, potentially leaving the selected row off-screen; the clamp also never scrolls *up* past the first rows correctly if heights differ. Confirmed wrong in source arithmetic; visual impact needs a running panel. Fix: position via the delegate's actual geometry (`resultsColumn.children[selectedIndex].y/height`) with `Flickable` bounds math.

## Rejected/softened claims from the earlier review

- **#4 (user services missed)**: accurate observation but a scope/feature gap, not a defect — system units are checked exactly as documented in the README ("Failed systemd services"). Track as enhancement.
- **#6 second half (470px hint row overflow)**: plausible but purely speculative; the `Text` has no `width` set so it may overflow its `Row`. Needs native validation, not asserted as a bug.
- No claim about the prototype's sample data was treated as a production bug, per instructions.

## Explicitly found safe / not bugs

- `copyCommand` quoting (`printf %s "$1"` with arg passing) and `openTerminal`'s `shellQuote` are correct; no injection via result text.
- `emit()` strips tabs/newlines from summary and command; `parseResults` rejoins `parts.slice(3)`, so extra tabs in commands survive round-trip. `title` fields are all hardcoded, so unsanitized title tabs are unreachable.
- `refresh()` reentry guard, `selectedIndex` clamping after `parseResults`, and the Timer's `running: root.opened` are correct.
- Prototype tab keyboard navigation (Arrow/Home/End + roving tabindex), `prefers-reduced-motion` handling, and hidden-page `[hidden]` toggling are correct.
- Memory/battery/temperature sysfs fallbacks guard division-by-zero and non-numeric reads correctly.
- `manifest.json` is consistent with the QML (`moduleName`/`ipcTarget` match the id).
